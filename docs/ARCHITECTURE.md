# Architecture

```text
Citizen browser
  |
  | IVR voice turn: MediaRecorder audio/webm
  v
Next.js frontend
  |
  | POST /api/voice/turn
  v
FastAPI backend
  |-- Sarvam Saaras v3 speech-to-text, language auto-detection
  |-- Sarvam-30B intent and response generation
  |-- Supabase Postgres transaction pooler
  |-- Sarvam Bulbul v3 text-to-speech
  v
Transcript, intent, actions, synthesized audio
```

## Realtime Path

```text
Next.js LiveKitRoom
  |
  v
LiveKit Cloud room
  |
  v
livekit_worker/agent.py
  |
  | citizen_health_turn tool
  v
FastAPI /api/text/turn
```

The IVR path is the canonical Sarvam audio path. The realtime worker is intentionally a separate deployable process so the backend keeps ownership of clinical/business decisions and Supabase writes.

## Key Backend Responsibilities

- Translate audio to text using Sarvam STT.
- Classify intents:
  - `hospital_navigation`
  - `eligibility_check`
  - `appointment_booking`
  - `maternal_health_reminder`
  - `nhm_programme_query`
  - `emergency`
  - `fallback`
- Persist every turn in `health_interactions`.
- Write appointment requests to `appointments`.
- Write reminder requests to `maternal_reminders`.
- Update `citizens.ayushman_status` as an eligibility pre-check.
- Return audio generated by Bulbul TTS.

## Deployment Notes

- Use Supabase transaction pooler for serverless-friendly connection management.
- Keep `prepare_threshold=None` for Psycopg when using transaction pooling.
- Store recordings in Supabase Storage or S3, then pass the URL into `health_interactions.audio_url`.
- Add RLS policies before exposing direct Supabase access from clients. This starter keeps all database access server-side.
